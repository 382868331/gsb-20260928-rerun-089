# 工业控制虚拟控制器

Go 提供控制模型、程序校验和扫描 API；React Flow 提供逻辑连线、输入操作和扫描观察页面。系统不连接任何真实工业设备。

## 运行

```bash
cd frontend && npm install && npm run build && cd ..
go run .
```

打开 `http://localhost:8080`。开发模式可分别运行 `go run .` 和 `cd frontend && npm run dev`。

## 扫描语义

- 固定扫描周期为 100ms，按拓扑顺序读取输入、求值内部功能块、更新输出。
- `SR` 为停止优先保持块，状态跨扫描保留；停止命令复位保持和定时器。
- `TON` 为通电延时，暂停扫描时累计值冻结，恢复后继续计时，不重新开始。
- 画布上可新增、删除、改名任意元件并修改 `TON` 预设值；删除元件时其连线一并删除。
- 编辑后的程序必须重新通过类型、端口、唯一输入、必需连接和无环校验；校验失败返回 422，错误信息在界面展示，旧版本继续运行，不会被部分替换或丢弃连线后继续。
- “保存并发布新版本”先原子写入 `data/program.json`（可用环境变量 `CONTROLLER_PROGRAM_FILE` 覆盖路径），再载入控制器；重启服务时从该文件恢复，输入/输出/内部元件完全来自当前程序，而非内置示例。
- 任意模式（停止/暂停/运行）都可发布新版本：模式保持不变，扫描计数清零，SR/组合逻辑状态复位；仅当新旧程序中存在**相同 id 且类型仍为 `TON`** 的定时器时保留 `elapsedMs/Q`（预设变更时按新预设重算 Q），删除、改型或新增的定时器一律从 0 开始。暂停发布后保留的定时器继续冻结，`GET /api/state` 的 `timers` 中可直接检查。
- 示例使用启动/停止按钮互锁、运行保持、500ms 延时和两个输出灯验证真实扫描结果。

## API

- `GET /api/program`：当前已发布程序（用于重开页面时恢复画布）。
- `PUT /api/program`：上传完整程序，校验通过后落盘并发布为新版本；非法程序返回 422，状态不变。
- `GET /api/state`、`PUT /api/inputs/{id}`、`POST /api/start|pause|stop|scans`：采样输入、模式控制与逐次扫描观察。
