# 工业控制虚拟控制器

Go 提供控制模型、程序校验和扫描 API；React Flow 提供逻辑连线、输入操作和扫描观察页面。系统不连接任何真实工业设备。

## 运行

```bash
cd frontend && npm install && npm run build && cd ..
go run .
```

打开 `http://localhost:8080`。开发模式可分别运行 `go run .` 和 `cd frontend && npm run dev`。

## 扫描语义

- 固定扫描周期为 100ms，按拓扑顺序读取输入、求值内部功能块、更新输出。
- `SR` 为停止优先保持块，状态跨扫描保留；停止命令复位保持和定时器。
- `TON` 为通电延时，暂停扫描时累计值冻结，恢复后继续计时，不重新开始。
- 编辑后的程序必须重新通过类型、端口、唯一输入、必需连接和无环校验后，才会作为新版本载入。
- 示例使用启动/停止按钮互锁、运行保持、500ms 延时和两个输出灯验证真实扫描结果。

## 版本与暂停的兼容语义

- 页面画布、输入、输出与定时器均来自服务端当前程序（`GET /api/state` 携带 `program`），版本变化后画布自动与服务端一致。
- `POST /api/program/preview` 在载入前校验并预览修订影响：互锁延时（TON 预设）变化、输入重命名、元件删除分别说明；非法连接返回 422，在生效前拒绝。
- `PUT /api/program?mode=preserve` 仅在变更兼容（无元件删除、无延时/类型修改）时保留已暂停状态：输入采样、定时累计、SR 保持与扫描计数延续，暂停不解除。
- `PUT /api/program?mode=restart`（默认）明确重新开始：版本递增，定时与保持状态清零，不会与已发生输出重复累计。
- 载入失败（校验 422 或保留模式不兼容）时服务端不修改任何运行状态，前端保留原暂停程序与本地编辑，不会清空画布或让用户误以为新版本已生效；载入成功后画布按服务端程序整体恢复。

## 扫描边界与输入试验分支

- `POST /api/boundaries` 把当前扫描序号上的输入、内部状态、定时累计与程序版本保存为只读边界。
- `POST /api/branches` 从某个边界建立试验分支；分支冻结边界时的程序版本，之后主程序修订（含元件删除）不影响分支核对。
- `PUT /api/branches/{id}/segment` 替换分支起点之后的一段虚拟输入并重新模拟；分支起点及之前的共同前缀只读，分支不会修改原执行已经发生的输出与历史。
- 每次替换后报告分支输出与原执行（同版本、同扫描序号）首次出现差异的位置，以及该位置涉及的内部状态。
- 每个分支区分三种状态：`created`（已创建尚无结果；创建失败不会产生半成品分支）、`applied`（替换输入已实际生效并完成模拟）、`abandoned`（放弃的中间分支，记录只读保留）。
- `POST /api/branches/{id}/fork` 在试验分支上继续派生子分支：派生点及之前的父分支输出是只读共同前缀；派生点之后父分支已模拟的候选输入默认继承，但每段都标注来源 `parent`（父分支模拟，非真实扫描）。
- 子分支替换与父分支替换范围重叠时，`overlapNotes` 与逐扫描 `origins` 说明本次实际采用的输入及来源（`original` 原执行真实扫描 / `parent` 父分支模拟 / `self` 本分支替换）；未执行的候选片段不会出现在真实扫描记录中。
- 子分支的首次输出差异与父分支记录比较，并报告差异扫描当时的内部保持状态（如 SR）与定时器累计（ElapsedMs/Q）；子分支结果绝不回写父分支或原执行。
- `POST /api/branches/{id}/abandon` 放弃中间分支：转为不可再编辑的只读保留记录；已有后代的对照依据在派生时已固定为快照，可继续替换、派生与对照。
- 比较面板明确区分三种结论：`diverged`（已比较，标出第一处可比较的真实输出差异及当时内部状态与定时累计）、`identical`（已比较且确实一致）、`no-baseline`（没有比较对象：原执行尚未覆盖该扫描范围，缺失记录不当作已执行扫描，也不判定一致）；部分扫描缺失时在 `missing` 中逐段列出。
- 每次对照固定采用程序修订、对照方输入版本与对应扫描范围，生成一份 `CompareReport` 并全部保留（`reports`）。子分支的对照依据是派生时父分支记录的快照（`baselineRecords` + `baseInputVersion`），父分支后续替换输入不会悄悄改变它，只会把子分支标记为 `compareStale`。
- `POST /api/branches/{id}/rebaseline` 在对照依据过期后由用户显式建立新的对照版本（重新快照父分支当前记录），旧报告保留；根分支对照原执行实时历史（只增不改），无需重建。
- `GET /api/trials?programVersion=&inputVersion=&scan=` 可沿程序修订版本、输入版本与扫描序号找回各次试验（含已放弃分支）。
- 新建分支的 `segment`/`records`/`origins`/`restarts`/`overlapNotes` 始终序列化为空数组而不是 `null`，前端另设错误边界，保存边界后建立分支不再因读取空值长度白屏。
- 定时器跨分支起点时以边界累计为依据继续计时；`POST /api/branches/{id}/restart` 让用户在分支起点明确重新开始某个元件（定时累计或保持值清零），并留下永久记录。
- 边界与分支持久化在 `branch_store.json`，保存重开后各分支的替换输入段、程序版本与扫描序号保持一致。
