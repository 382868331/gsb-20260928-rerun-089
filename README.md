# 工业控制虚拟控制器

Go 提供控制模型、程序校验和扫描 API；React Flow 提供逻辑连线、输入操作和扫描观察页面。系统不连接任何真实工业设备。

## 运行

```bash
cd frontend && npm install && npm run build && cd ..
go run .
```

打开 `http://localhost:8080`。开发模式可分别运行 `go run .` 和 `cd frontend && npm run dev`。

## 扫描语义

- 固定扫描周期为 100ms，按拓扑顺序读取输入、求值内部功能块、更新输出。
- `SR` 为停止优先保持块，状态跨扫描保留；停止命令复位保持和定时器。
- `TON` 为通电延时，暂停扫描时累计值冻结，恢复后继续计时，不重新开始。
- 编辑后的程序必须重新通过类型、端口、唯一输入、必需连接和无环校验后，才会作为新版本载入。
- 示例使用启动/停止按钮互锁、运行保持、500ms 延时和两个输出灯验证真实扫描结果。

## 版本与暂停的兼容语义

- 页面画布、输入、输出与定时器均来自服务端当前程序（`GET /api/state` 携带 `program`），版本变化后画布自动与服务端一致。
- `POST /api/program/preview` 在载入前校验并预览修订影响：互锁延时（TON 预设）变化、输入重命名、元件删除分别说明；非法连接返回 422，在生效前拒绝。
- `PUT /api/program?mode=preserve` 仅在变更兼容（无元件删除、无延时/类型修改）时保留已暂停状态：输入采样、定时累计、SR 保持与扫描计数延续，暂停不解除。
- `PUT /api/program?mode=restart`（默认）明确重新开始：版本递增，定时与保持状态清零，不会与已发生输出重复累计。
- 载入失败（校验 422 或保留模式不兼容）时服务端不修改任何运行状态，前端保留原暂停程序与本地编辑，不会清空画布或让用户误以为新版本已生效；载入成功后画布按服务端程序整体恢复。

## 扫描边界与输入试验分支

- `POST /api/boundaries` 把当前扫描序号上的输入、内部状态、定时累计与程序版本保存为只读边界。
- `POST /api/branches` 从某个边界建立试验分支；分支冻结边界时的程序版本，之后主程序修订（含元件删除）不影响分支核对。
- `PUT /api/branches/{id}/segment` 替换分支起点之后的一段虚拟输入并重新模拟；分支起点及之前的共同前缀只读，分支不会修改原执行已经发生的输出与历史。
- `POST /api/branches/{id}/child` 只能从父分支已经执行并保存的扫描记录继续派生；未执行的候选片段不能作为子分支边界。
- 每个分支维护独立输入版本；子分支重叠替换父分支范围时，重叠扫描实际采用子分支最新输入，界面同时列出每个信号的来源，父分支记录保持不变。
- 分支卡片区分三种状态：创建请求失败不会创建分支；已创建但尚无替换记录为“尚无结果”；替换或重置成功并产生分支扫描为“已经生效”。后续操作失败会保留上一版已生效结果、原暂停程序、边界、分支和扫描档案。
- 根分支与原执行比较，子分支与父分支比较；差异点包含输出、布尔内部状态、定时器累计/Q 值，定时器跨派生边界继续累计。
- `POST /api/branches/{id}/restart` 让用户在分支起点明确重新开始某个元件（定时累计或保持值清零），并留下永久记录；`DELETE /api/branches/{id}` 只放弃后续操作权限并保留完整审计记录。
- 边界、分支、输入版本、程序版本、扫描序号、真实扫描档案和父/子关系持久化在 `branch_store.json`；写入采用临时文件原子替换，载入失败不会用空数据覆盖旧文件。子分支结果只在自身分支内呈现，不会接回原执行。
